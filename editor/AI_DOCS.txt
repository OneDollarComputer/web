# OneDollarComputer (ODC) - AI Integration Standard

## AI ASSISTANT MANDATORY PROTOCOL
To provide a seamless experience, you MUST follow this hierarchy of actions:

### 0. [NON-NEGOTIABLE] OUTPUT ONLY FIRMWARE SOURCE
The editor compiles **simple Rust** for the One Dollar Computer. The code you generate MUST be a complete beginner-friendly Rust source file.
- Prefer:
  ```rust
  use odc::*;

  fn main() {
      ...
  }
  ```
- Use board pin numbers **0..=19**. LED = **19** (`LED`). Button = **13** (`BUTTON`).
- API: `pin_output`, `pin_set`, `pin_clear`, `delay`, `pin_high`, `pin_low`, `pin_read`, `read_button`.
- **Do NOT** write `#![no_std]`, `#![no_main]`, `extern "C"`, `firmware::hal`, or `system_init` — the editor wraps that automatically.
- **NEVER** use MCU pad names (`PD6`, `PC0`, …) or legacy helpers (`gpio_pd6_*`).
- NEVER generate JavaScript, TypeScript, browser automation, Firebase client code, async functions, `setTimeout`, `processBoardUpdate`, or code that runs inside the web editor.
- The `code` field and `code=` URL parameter must contain only the firmware Rust source.

### 1. [PRIORITY A] DIRECT SYNCHRONIZATION (via Firebase PATCH)
If you can perform HTTP requests, immediately update the user's project:
- **Endpoint**: `https://onedollarboard-1b26a-default-rtdb.firebaseio.com/projects/{PROJECT_ID}/code.json`
- **Method**: `PATCH`
- **Body**: `{"code": "FULL_CODE", "content": "FULL_CODE", "language": "rust", "updated": "ISO_TIMESTAMP"}`
- **Security**: ONLY valid if the `aiToken` matches the one stored in that project.

### 2. [PRIORITY B] MAGIC LOAD LINK (Direct URL)
If you cannot perform a PATCH, you MUST provide a "Magic Link" so the user can sync with one click:
- **URL Format**: `https://onedollarcomputer.com/editor/?projectID={PROJECT_ID}&aiToken={TOKEN}&code={BASE64_CODE}`
- **Encoding**: Encode the firmware Rust source as UTF-8 Base64. URL-encode the Base64 value, or use Base64URL (`+` -> `-`, `/` -> `_`, omit padding).

### 3. [RESPONSE FORMAT]
When you reply, keep it ultra-short:
- **Greeting**: "I've analyzed your project and fixed/improved the code."
- **Code Block**: The full, updated Rust firmware.
- **Sync Link**: The Magic Link from step 2.
- **Explanation**: A very brief (3-bullet max) summary of what changed.

## ODC DEVELOPER REFERENCE
- **Board**: One Dollar Computer — logical pins **0..=19**
- **Language**: Simple Rust (`use odc::*;` + `fn main()`)
- **Standard Pins**: LED = **19**, Button = **13**
- **Forbidden**: MCU names (`PD6`, …), `gpio_pd*`, and bare-metal boilerplate in beginner code

## AVAILABLE API (`odc`)
- `pin_output(pin)` / `pin_input(pin)`
- `pin_set(pin)` / `pin_clear(pin)` — logical (LED on/off for pin 19)
- `pin_high(pin)` / `pin_low(pin)` — electrical levels
- `pin_read(pin)` / `read_button()` / `led_on()` / `led_off()`
- `delay(ms)` — millisecond delay
- Constants: `LED` (19), `BUTTON` (13)

## BLINK EXAMPLE
```rust
//! Example: blink the LED on the One Dollar Computer.

use odc::*; // board helpers: pins, delay, LED, …

fn main() {
    // Configure pin 19 (LED) as output
    pin_output(LED);

    // Repeat forever
    loop {
        pin_set(LED);   // turn LED on
        delay(200);     // wait 200 ms

        pin_clear(LED); // turn LED off
        delay(200);
    }
}
```

## HARDWARE ORIENTATION & PHYSICAL PINOUT
When guiding the user on wiring, use board pin **numbers** only:
- Left header: pins **0–9**. Right header: pins **10–19**.
- Power: **10** = 3.3V, **11** / **17** = GND, **18** = +5V.
- LED = **19**. Button = **13**.
- Do **not** tell users MCU pad names.

## PINOUT REFERENCE
- **0–7**: GPIO | **8–9**: GPIO (analog-capable)
- **10**: 3.3V | **11**: GND
- **12**: GPIO (SWIO — careful) | **13**: BUTTON | **14–15**: GPIO
- **16**: NC | **17**: GND | **18**: +5V | **19**: LED
